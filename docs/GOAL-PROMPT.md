/goal Build Descent of Nations: a deterministic, batch-parallel Rust reimplementation of the Rise of Nations: Extended Edition simulation, derived from the binary rather than from community documentation, bit-exact wherever we can prove it, and shaped from day one to become an RL environment capable of training a SOTA self-play player-AI.

READ FIRST, EVERY SESSION: /Users/ember/dev/don/docs/CHARTER.md — it holds the methodology law, the fidelity tiers, the staged roadmap, the swarm doctrine, and the box-safety rules. /Users/ember/dev/don/docs/binary-ground-truth.md holds what we have already derived from the binary; do not re-derive it, and do not contradict it without new evidence. /Users/ember/dev/don/docs/prior-art-survey.md is CROSS-CHECK MATERIAL ONLY — never a source for an implemented value.

The one rule that matters most: ground truth is the binary and the shipped data files. Before writing any constant or formula, say out loud where it came from — a binary address, or a file and line in ron-data/. If the honest answer is "the wiki says so", STOP and go get it from the binary. Maintain the provenance ledger; a mechanic without a ledger entry is not done. Label every mechanic with its fidelity tier (A = SMT-proven over the full input domain; B = differentially tested against the real code, always stated with N and the input distribution; C = behaviorally faithful with measured divergence). Never inflate a tier, and never let differential testing call itself verification — we hold no formal semantics of Rust or x86, so nothing here is "verified" in the proof-assistant sense. Describe the work at that resolution in commits, in docs, and to me.

Current thrust: stage 1, loader recovery. FUN_00570170 in the Ghidra project at /Users/ember/dev/don/re/ghidra (project "ron", program riseofnations.exe, 47177 functions) is the rules.xml constant loader — it xrefs the UTF-16 lowercase strings flank_bonus, cavalry_flank_bonus, vehicle_flank_bonus, siege_attrition and accel_train. Decompiling it should yield the complete mapping from rule name to struct field, mechanically, for every constant in rules.xml. FUN_0061c490 xrefs progression and FUN_0065fc00 xrefs recharge; both are unitrules-side and need the same treatment. Note the loader parses rationals out of English prose (values look like "1/16 tile (calibration for unit spacing in formations)"), so the tokenizer semantics are themselves ground truth we must replicate exactly. Also worth an early look: the SyncDisplay-adjacent lockstep checksum routine, because it defines which state is sim-critical, and the seven non-IEEE CRT transcendentals, because whether sim code reaches them decides whether whole-sim bit-exactness is achievable at all.

Fan out with workflows wherever the work is genuinely parallel — loader lanes per XML file, RE lanes per mechanic, adversarial audit lanes that read the actual tier claims rather than trusting lane self-reports. Follow the swarm doctrine in the charter: absolute paths and real addresses in every lane prompt, and make the project-correct choice the DEFAULT you write into the prompt, because lanes take whatever default you give them. Keep waves modest unless I say go wide.

Work it self-paced and by your own taste. Pick the highest-value thread yourself; reversible decisions are yours. Stop only for genuinely irreversible things or a decision only I can make. I would love bit-exactness, and I would love to someday put a real player-AI on top of this — let those pull the design, but never let them pull a fidelity claim past what we actually earned.
