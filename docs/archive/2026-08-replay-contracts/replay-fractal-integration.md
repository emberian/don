# Replay fractal integration handoff

Status: the real `don-replay` initial-map transaction now reaches
`TerrainGroups::place_all` when a lawful installed `Data/tilesets.xml` source
is supplied. Without that file it still advances every independent earlier
stage, records the exact missing path/error, and stops immediately before
`TerrainGroups::fill_fertile`.

## Corrected retail order

The relevant ordinary procedural path is:

```text
Map::make (0x0068bc90)
  -> Map::load_map_data (0x0069dad0)
     -> Map::init_map_data (0x0069f250)
        -> tileset Random::get (0x0069f97e)
     -> TerrainGroups::init_tileset_data (0x006a61f0)
        -> Fractal::init call (0x006a6453)
  -> orientation Random::get (0x0068bd6a)
  -> selected make_continents virtual
  -> common region/coastline continuation
  -> TerrainGroups::fill_fertile (0x006a6f90)
  -> TerrainGroups::place_all (0x006a70d0)
```

The earlier continent adapter started its `Random` directly from the replay
seed. That skipped the weighted tileset-selection draw(s) performed during
`load_map_data`. Retail applies the default MAP first and then the selected MAP;
when both contain a TILESET table, both tables consume their own draw and the
selected result overrides the default result. `resolve_tile_selection` retains
these ordered passes independently of `tilesets.xml`, and the replay-owned continent call starts from
`TileSelectionBoundary::main_random_state_after`. The old seed-start wrappers
remain for isolated unit tests; the initial replay flow uses only the explicit
RNG-state entry point.

## Typed installed-data seam

`InitialItemReconstruction::advance_continent_prefix_with_tilesets` accepts a
caller-owned `&Path` to installed `Data/tilesets.xml`. Its default and selected
map-style paths come from the already catalog-validated
`MapStyleStaticData::{default_source, selected_source}` evidence; callers cannot
substitute an unrelated style XML through this API.

The harness uses `<ron-data-root>/tilesets.xml`. That location remains
gitignored. No retail tileset bytes, observed clump factors, or assumed
baseland-row counts are checked in.

Admission is staged:

- Map-style tile selection must resolve before any world mutation. Failure is
  a transactional `InitialItemReconstructionError::TileSelection`.
- If installed tileset data is missing or malformed, its precise
  `FractalBoundaryError` is retained in `fertility_error`. The corrected
  continent and coastline stages still execute from the proven post-tileset
  RNG state, then stop at `terrain_groups_fill_fertile`.
- If the full fertility input resolves, the generated byte plane and
  partitions are applied through don-sim's complete `fill_fertile` port. The
  receipt and static evidence remain attached to the plan, whose exact next
  boundary becomes `terrain_groups_place_all` at `0x006a70d0`.
- A `fill_fertile` shape/access error is transactional: neither authoritative
  world/region storage nor the plan boundary is committed.

## Corpus impact

The checked-in `ron-data` extraction currently has map-style XML but no
`tilesets.xml`. Corpus runs therefore gain the corrected tileset RNG draw and
report the selected tileset, bucket, draw, and post-selection RNG state. Runs
whose continent path reaches the common tail remain honestly blocked at
`terrain_groups_fill_fertile`, now with the concrete absent path reported.

Once a user places their lawful installed file at `ron-data/tilesets.xml`, the
same corpus path executes `fill_fertile` and reports its fertile-cell write count.
The frontier then moves to `TerrainGroups::place_all`: its terrain-group
runtime tables and expression resolution, not the fractal plane or baseland
partitions, are the next substantial producer input.

The self-contained integration fixture does not reproduce shipped static data.
It uses two invented tilesets and a 16-by-16 Old World input to freeze:

- tileset draw/bucket and post-selection RNG handoff before orientation;
- full static-source admission through a temporary external XML path;
- exact per-cell `land_sub` buckets from the admitted plane/partitions;
- the `fill_fertile` receipt and `place_all` boundary; and
- missing/malformed installed-input behavior without suppressing independent
  earlier work.
